## Design Specificity Verdict

**LLM assessment**: The ledger grid is genuinely authored for this product — continuous 1px channels, 5×5 L-brackets, mono meta rows, posters-as-palette. It survives both themes and mobile. Three specificity failures: (1) the hero is a category-interchangeable SaaS landing block whose single action is a dead newsletter; (2) the detail page — where every deep link lands — delegates its primary artifact to X's embed placed above the H1 and has no in-site player, even though in-site proxy playback is the product's stated differentiator; (3) the admin primary button is broken by a CSS layering bug. Submit is the most honest surface; About is correctly quiet (with a whitespace bug); Admin is appropriately utilitarian.

**Deterministic scan**: 11 advisory `design-system-font-size` hits, all in src/components/ui/ (12px/13px/14px on Base UI primitives); src/pages clean. Built HTML confirms 3 ship to production (category select 13px on /, submit button 14px + 5×13px on /submit/). 12px/14px are off the documented ramp (10, 11, 13, 16, 22, clamps); the 13px hits are arguably misapplied to chrome that should be 11px mono per the Mono-Is-Chrome rule. 1 `em-dash-overuse` warning on dist/index.html is a false positive — the 49 em-dashes come from catalog data ("Maker — tagline" card format), not prose. Detector missed the invisible-button bug and the light-mode focus-ring contrast failure that LLM review caught.

## What's Working

1. The ledger grid is a real, ownable idea executed with discipline — it survives both themes and mobile.
2. Playback engineering and failure handling: proxy routing, autoplay fallback, error state with X fallback, touch-visible controls.
3. Keyboard/URL craft: ⌘K on every page, Esc with aria-keyshortcuts, shareable filter URLs, scroll/focus restoration.

## Priority Issues

- **[P1] Invisible label on the shared primary Button.** Why: `button { color: inherit }` in global.css is unlayered and beats `@layer utilities` `.text-background`; /admin "Enter admin" renders as an empty pill (verified: label rgb(9,9,11) on bg rgb(9,9,11)). Fix: move the reset into `@layer base`, not per-button `!important` patches. Suggested command: `$impeccable harden`.
- **[P1] Fake newsletter in the hero.** Why: the first-visit action collects an email and confesses it does nothing — the only place the site takes something and gives nothing back. Fix: remove it, wire it up, or replace the hero action with the real loop (watch/browse). Suggested command: `$impeccable distill`.
- **[P1] Detail page has no in-site playback.** Why: every search result, share, and crawler lands here, and the product's differentiator (proxy playback) is absent; the X embed sits above the H1 and inverts hierarchy, degrading to raw tweet text when widgets.js is blocked. Fix: make the detail page play the video (reuse the modal player or embed one) and move the embed below the facts. Suggested command: `$impeccable shape` (or polish with this brief).
- **[P2] Focus ring fails light-mode contrast.** Why: #6b97ff 1px on #fafafa ≈ 2.7:1, below WCAG 2.4.11's 3:1; also the global focus outline is rounded 8px on square chrome, against the system's own shape rule. Fix: darken the light-mode focus ring and square the outline on chrome. Suggested command: `$impeccable audit`.
- **[P3] About page missing spaces.** "via theSubmit form", "added tosrc/data/videos.json" from Astro whitespace collapsing (about.astro:43-46). Fix: explicit `{" "}`. Suggested command: `$impeccable polish`.

- **Alex (power user)**: well served (⌘K, Esc, URL state). Gaps: no arrow-key grid nav, no next/prev video (the 016/724 counter teases exactly this), palette selection invisible to AT.

Positives: reduced-motion, touch fallbacks, aria-current, sr-only titles.

## Questions to Consider

- If the detail page cannot play the video, what is the modal player for? Should the detail page BE the player, with the ledger table beneath?
- Why does the first screen contain zero posters when posters are the palette? What if the hero were one playable launch frame?
- 016 / 724 frames the catalog as a sequence — what breaks if ←/→ actually step through it?
- The site exists because X is ephemeral — yet detail playback depends entirely on widgets.js succeeding. Is the archival promise kept where it matters most?
- What would the homepage lose if the hero were deleted and the ledger started at the fold?
